# FORK.md

This is the LAMB fork of [CADCraft](https://github.com/storytold/cadcraft): LAMB (a 2D-first
architectural drafting tool with views, levels, links and derived 3D) rebuilt on CADCraft's
headless crates. LAMB's own code lives in `crates/lamb-core` (no CADCraft dependency) and
`crates/lamb-cadcraft` (the adapter on `cadcraft-engine`). The `lamb` branch tracks upstream `main`
and takes upstream changes by **merge, never rebase**, so every patch to CADCraft's own crates stays
visible and is listed below with its upstream PR.

| Patch | Files | Why | Upstream PR |
|---|---|---|---|
| 2. Extension slots | `crates/doc/src/lib.rs`, `crates/doc/src/entity.rs`, `crates/doc/src/tables.rs`, `crates/engine/src/lib.rs`, `crates/engine/src/ext_tests.rs`; DXF: `crates/io/src/dxf_ext.rs`, `crates/io/src/dxf_write.rs`, `crates/io/src/dxf_read.rs`, `crates/io/src/lib.rs`, `crates/io/src/ext_dxf_tests.rs` | `pub type Extension = BTreeMap<String, serde_json::Value>` keyed by application name (the DXF APPID idea); `pub ext: Extension` on `Common`, `Layer` and `Drawing` (serde `default` + `skip_serializing_if = is_empty`, so existing serialized forms are unchanged while empty). Entity copies (COPY, MIRROR, ARRAYRECT, OFFSET, ROTATE copy, COPYCLIP/PASTECLIP) clone it (an associative array keeps it on the objects it moves into its source block) and undo/redo restore it through the `Arc<Drawing>` snapshots; LAMB keeps its data under `ext["LAMB"]`. DXF round-trips it: each entity/layer key `K` is xdata under its own registered APPID `K` (verbatim) shaped like `array_xdata` (`1001 K`, `1000 EXT`, `1002 {`, JSON in ≤240-cost `1000` strings, `1002 }`), spliced at the end of the entity's own record before any VERTEX/ATTRIB/SEQEND; `Drawing.ext` is one named-object-dictionary XRECORD `CADCRAFT_EXT_<key>` per key. The reader only claims xdata with the `EXT` marker that parses as JSON, and drops claimed apps from the kept foreign xdata so a removed slot stays removed. Keys that are invalid symbol names or equal (any case) to CADCraft's own APPIDs are skipped on write; keys equal but for case keep the first. Not enforced: AutoCAD's ~16 KB xdata-per-object cap; untested: DWG (rides the DXF writer) and an AutoCAD round-trip. | not yet submitted |
| 3. After-command observers | `crates/engine/src/lib.rs`, `crates/engine/src/observer_tests.rs` | `pub observers: Vec<AfterCommand>` on `Session` (`AfterCommand = fn(&mut Session, &Arc<Drawing>)`, the drawing before the command). Called in registration order after CADCraft's own group/constraint/associativity passes in `execute` (undoable, successful commands on the same drawing) and `finish`, only when the drawing changed, so their edits share the command's undo step; undo/redo never trigger them. How LAMB runs link maintenance, solid-cut reconciliation and derived-view regeneration. | not yet submitted |

Process-global; registering after the first `command_specs()` call returns `Err`. How LAMB registers `NEWPLAN`, `PLACEVIEW` and its own `fillet`. | not yet submitted |
